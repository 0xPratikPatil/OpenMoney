## Locked-in decisions (from specs.md / user)

- **Language**: TypeScript strict mode (`strictNullChecks`, `noImplicitAny`, `exactOptionalPropertyTypes`). Zero `.js` files anywhere in the repo.
- **Runtime**: Bun 1.2+ for all dev, test, and production API serving. Not Node.js.
- **Package manager**: Bun (not npm, not pnpm, not yarn). Monorepo via Bun workspaces.
- **Auth**: better-auth with Prisma adapter. Self-hosted. User data stays in our Postgres.
- **ORM**: Prisma. Schema auto-generated by better-auth CLI, then extended.
- **Backend API**: Hono 4 (standalone server, not Next.js API routes). Runs on Bun. WebSocket for real-time.
- **Frontend**: Next.js 15 App Router. TypeScript-only. Tailwind CSS.
- **UI Library**: `packages/openmoney-ui/` — self-owned design system package consumed by `openmoney-web`. Uses shadcn/ui primitives as base, all components owned within the monorepo. Future-ready for custom theming.
- **Docs**: Fumadocs (not Nextra, not Docusaurus). OpenAPI auto-docs from Zod schemas.
- **Database**: PostgreSQL + TimescaleDB extension. Hypertables for time-series market data.
- **Cache/queue**: Redis (sessions, rate limiting, pub/sub, Streams for backpressure).
- **Data validation**: Zod everywhere. `@hono/zod-validator` for API, shared Zod schemas in `packages/openmoney-schemas`.
- **Quant models**: TypeScript-first for 70% of models (via `trading-signals`, `nanuquant-ts`, `mathjs`). Python subprocess bridge (`Bun.spawn()`) only for GARCH and advanced statistical models.
- **Data sources**: Bring-your-own-API-key model (like OpenBB). Not bundled.
- **Provider architecture**: Direct port of OpenBB's Provider → Fetcher → TET pattern, but in TypeScript. Every data source is an interchangeable adapter.
- **API routing**: No version prefixes in URL paths (no `/v1/`). Versioning via package version and content negotiation. Routes follow domain hierarchy: `/api/equity/historical`, `/api/portfolio/:id/risk`, etc.

## Framework quirks to remember

- **better-auth + Prisma**: Run `npx auth@latest generate` to auto-generate Prisma schema from auth config, then `npx prisma migrate dev` to create migrations. The CLI does NOT run migrations for you.
- **Hono on Bun**: Export `{ port: number, fetch: app.fetch }` from entry file. Bun reads this. WebSocket support via `hono/bun` import.
- **Hono + Next.js**: Use `hc` (Hono Client) from `hono/client` for type-safe API calls. Share route types via `packages/openmoney-schemas`.
- **TimescaleDB with Prisma**: TimescaleDB is a Postgres extension. Prisma sees it as regular Postgres. Hypertables are created via raw SQL migrations (not Prisma schema). Mix `prisma migrate` for relational schema + custom SQL files for hypertable setup.
- **No JavaScript**: Not even config files. Next.js config, Hono config, Tailwind config — all `.ts`. Bun handles TS natively.
- **Python bridge**: For quant models, use `Bun.spawn(["python3", "-c", script])` with JSON stdin/stdout. Not a full microservice in MVP.
- **Provider infrastructure is an OpenBB port**: The `packages/provider-core/` implements `AbstractFetcher<Q, D>`, `ProviderRegistry`, and `QueryExecutor`. Every provider extends `AbstractFetcher` with the TET lifecycle. Consult `reference/openbb_platform/core/openbb_core/provider/abstract/` before building this.
- **Zod schemas are OpenBB standard_models ports**: Each file in `packages/shared/src/schemas/` should correspond to a file in `reference/openbb_platform/core/openbb_core/provider/standard_models/`. The Zod schema defines both `QueryParams` (input) and `Data` (output).
- **Multi-provider pattern**: Multiple providers can register fetchers for the same model name (e.g., `equity/historical`). The `provider` query parameter selects which provider to use. Users configure default provider per data type in settings. See OpenBB's `ProviderChoices` pattern in the reference.
- **No URL version prefixes**: Routes like `/api/v1/equity/historical` are `/api/equity/historical`. Versioning is handled through package release management and content negotiation.

## Key commands

```bash
bun install                    # install everything (monorepo)
bun run dev:api                # start Hono API server (port 4000)
bun run typecheck              # tsc --noEmit (strict mode)
bun run test                   # all tests
bun run test:provider-core     # provider-core tests only (8 tests)
bun run dev                    # start all services in dev mode
bun run lint                   # ESLint + Prettier
bun run db:migrate             # prisma migrate dev
bun run db:generate            # prisma generate
npx auth@latest generate       # better-auth schema generation
```
