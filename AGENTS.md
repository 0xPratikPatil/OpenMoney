## Locked-in decisions (from specs.md / user)

- **Language**: TypeScript strict mode (`strictNullChecks`, `noImplicitAny`, `exactOptionalPropertyTypes`). Zero `.js` files anywhere in the repo.
- **Runtime**: Bun 1.2+ for all dev, test, and production API serving. Not Node.js.
- **Package manager**: Bun (not npm, not pnpm, not yarn). Monorepo via Bun workspaces.
- **Auth**: better-auth with Prisma adapter. Self-hosted. User data stays in our Postgres.
- **ORM**: Prisma. Schema auto-generated by better-auth CLI, then extended.
- **Backend API**: Hono 4 (standalone server, not Next.js API routes). Runs on Bun. WebSocket for real-time.
- **Frontend**: Next.js 15 App Router. TypeScript-only. Tailwind CSS.
- **Docs**: Fumadocs (not Nextra, not Docusaurus). OpenAPI auto-docs from Zod schemas.
- **Database**: PostgreSQL + TimescaleDB extension. Hypertables for time-series market data.
- **Cache/queue**: Redis (sessions, rate limiting, pub/sub, Streams for backpressure).
- **Data validation**: Zod everywhere. `@hono/zod-validator` for API, shared Zod schemas in `packages/shared`.
- **Quant models**: Python subprocess bridge (`Bun.spawn()`) for statsmodels/arch/numpy/QuantStats. Not a microservice in MVP.
- **Data sources**: Bring-your-own-API-key model (like OpenBB). Not bundled.

## Framework quirks to remember

- **better-auth + Prisma**: Run `npx auth@latest generate` to auto-generate Prisma schema from auth config, then `npx prisma migrate dev` to create migrations. The CLI does NOT run migrations for you.
- **Hono on Bun**: Export `{ port: number, fetch: app.fetch }` from entry file. Bun reads this. WebSocket support via `hono/bun` import.
- **Hono + Next.js**: Use `hc` (Hono Client) from `hono/client` for type-safe API calls. Share route types via `packages/shared`.
- **TimescaleDB with Prisma**: TimescaleDB is a Postgres extension. Prisma sees it as regular Postgres. Hypertables are created via raw SQL migrations (not Prisma schema). Mix `prisma migrate` for relational schema + custom SQL files for hypertable setup.
- **No JavaScript**: Not even config files. Next.js config, Hono config, Tailwind config — all `.ts`. Bun handles TS natively.
- **Python bridge**: For quant models, use `Bun.spawn(["python3", "-c", script])` with JSON stdin/stdout. Not a full microservice in MVP.
